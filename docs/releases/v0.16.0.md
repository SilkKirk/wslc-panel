# v0.16.0 —— 数据库能连远程了

这一版把数据库功能从「在容器里跑 `mysql` / `psql` 客户端」换成了**面板自己连**。
一句话区别：**以前必须有容器才能查库，现在填一条连接串就能连任何地方的数据库**。

---

## 连接串：通用数据库查询的入口

数据库页 →「基础信息」→ 连接卡，多了一格：

```text
连接串（可选，填了就走原生连接）
[postgres://user:pass@db.example.com:5432/shop    ]
[应用连接串]   当前：在容器里执行（未使用连接串）
```

填了 → 右边那句话变成 `当前：原生连接 postgres://user:***@db.example.com:5432/shop`，
之后 SQL 控制台、表结构树、库列表**全部走面板自己的 TCP 连接**。留空再点一次就回到容器里执行。

支持的形状：

```text
postgres://user:pass@host:5432/dbname
postgresql://user@host/dbname              （没有口令、没有端口时用默认值）
mysql://root:p%40ss@10.0.0.5:3306/shop     （口令里的 @ 要编码成 %40）
postgres://u:p@[::1]:5433/db               （IPv6 也支持）
```

几条刻意的设计：

- **`?sslmode=require` 这类查询参数直接报错**，不静默忽略。各引擎的参数名都不一样
  （MySQL 是 `ssl-mode`、PostgreSQL 是 `sslmode`），猜错比不支持更糟；而静默丢掉
  会让用户以为"我明明写了 require"。
- **口令不进界面**：卡上显示的是 `user:***@host`。那一行会被截图发到 issue 里。
- **引擎必须和这一页对得上**：把 PostgreSQL 连接串填进 MySQL 页会得到明确拒绝，
  而不是"查询走 PG、库列表按 MySQL 元数据去查"那种半对半错的状态。
- **换连接会清空旧的对象树** —— 否则树里还是上一个连接的表。

## 两种引擎都支持

| | PostgreSQL | MySQL / MariaDB |
|---|---|---|
| 原生连接 | ✅ | ✅ |
| SQL 控制台 | ✅ | ✅ |
| 表结构树 | ✅ | ✅ |
| 库列表 / 用户 | ✅ | ✅ |
| 容器 exec 兜底（留空连接串） | ✅ | ✅ |

## 为什么不影响原来能用的东西

**连接串留空时，一切照旧** —— 还是容器里那个 `mysql` / `psql` 客户端。
原生连接是叠加的一条路，不是替换。

## ⚠️ 这一版**不支持 TLS**

云数据库（Supabase / Neon / 阿里云 RDS 之类）几乎都强制 TLS，**连那些会失败**。
失败时给的是一句明确的话，不会静默降级成明文：

```text
TLS 握手失败：PostgreSQL 的 TLS 还没接（现在只能连明文库）
```

**这是刻意的。** 静默用明文连上去的后果是：口令和查询内容在网线上裸奔，
而界面上一切正常 —— 那比连不上糟得多。

所以这一版能连的是：**本机 / 内网 / 任意允许明文连接的库**。

## 结果表格的一个细节

MySQL 的二进制列（`BLOB` / `VARBINARY`）现在显示成 `0x001FFF`，
而不是一串 `�`。判据用列自己的字符集 id（`63` = binary），做法参考 dbx。

以前那种显示看起来像"数据坏了"，其实只是我们拿二进制当文本读。

## 已知缺口

- 连接**不记住**：关掉页面再进来要重填
- 入口仍绑容器：远程库也得先有个容器才能进这个页面
- TLS 未支持（见上）
- MySQL 的 `TEXT` 长文本没有做截断，超大字段会让结果表变慢

## 内部变化（给以后翻代码的人）

- 新增 crate **`wslc-db`**（MSRV 1.85）：`ConnSpec` / `parse_dsn` / `Session` trait /
  `PgSession` / `MySqlSession`。单独一个 crate 是因为 `postgres` 0.19 要 1.85，
  而 `wslc-core` 承诺 1.75。
- 用**同步**驱动而不是 `sqlx` / `tokio-postgres`：这个项目的铁律是"阻塞调用放
  `background_executor`"，同步驱动天然符合；异步驱动要桥 tokio runtime，
  多一层就多一类"卡界面 / 死锁"的 bug。
- 元数据解析**没有**为原生连接写第二套：MySQL 侧把单元格还原成 `-B -N` 那种
  TSV 文本，喂给原来那套解析函数（一套解析两条路，避免行为差异）。
- PostgreSQL 侧用 `simple_query` 拿文本值（零类型映射）+ 一次 `prepare` 拿列名。
- `wslc-db` 有 27 条单元测试，全部在 `core` job 里真跑。
