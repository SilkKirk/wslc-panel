# v0.11.0

数据库的 SQL 界面重做。原来的「查询控制台」是**一段纯文本**（`mysql --table`
打的 ASCII 表格），看不懂也没法用；现在是**能点的表格 + 库表树 + 导出**。

### 变化

**结果变成真正的表格。** 列头可点排序、列可拖宽、单元格可选中、
数字右对齐、空值灰斜体显示 `NULL`。几万行也不卡（虚拟滚动，只渲染可见行）。

**左侧多了库 / 表树。** 一条 SQL 拿全整棵树（实测 118 张表 / 0.08 秒），
带搜索过滤。点表名自动填 `SELECT * FROM \`库\`.\`表\` LIMIT 200` 进编辑区
—— 是**填进去**不是直接执行，你还有机会加 `WHERE` 或发现自己点错了表。

**多条语句可以一次跑完。** 一次贴进 `SELECT ...; UPDATE ...; SELECT ...`，
面板会切成一条条执行，结果按标签页分开看。之前这种写法多个结果
会**粘在一起**分不清哪行属于哪条。

**可以导出 CSV。** 弹保存对话框、预填文件名、覆盖前确认，写盘是原子的。

### 关于空值

`mysql` 的批量输出里，`NULL` 和空字符串长得**完全一样**，面板不去区分它们
（区分要换成 XML 输出，为一个不常看的细节不值）。
表格里它们都显示成灰斜体的 `NULL` —— 至少让你知道「这里读到了一个空值」，
而不是一片留白让你以为表格画错了。

### 需要知道的两件事

- **多条语句是逐条执行的**，每条有约 70ms 的固定开销。贴 30 条进去会明显慢
  —— 界面上写了这句话。
- **存储过程 / 触发器 / 函数定义**（`CREATE PROCEDURE ... BEGIN ... END`）
  这一版不支持：里面的 `;` 需要 `DELIMITER` 才能正确切分，而 `DELIMITER`
  是客户端命令、`mysql -e` 也不认。遇到这类语句会整段当一条交给服务端报错。

### 其它

- 空结果集和 `SET` / DDL 这类没有结果集的语句，输出都是**零字节**，分不出来。
  界面上统一说「执行成功，没有返回行」。
- 系统库（`mysql` / `information_schema` / `performance_schema` / `sys`）
  不在树里显示 —— 它们上千张表会把你自己的库淹掉。

### 需要实机确认

- 库表树 220px 够不够宽（长表名会截断）
- 控制台浮层加宽到 1120px 在你的窗口下会不会太满
- 结果表格固定 360px 高度够不够
- 导出：保存对话框弹不弹、中文路径对不对
