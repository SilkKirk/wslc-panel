# v0.12.0

SQL 控制台从**浮层**变成了**整页工作区**，编辑器换成带 SQL 语法高亮的多行编辑器。

### 变化

**不再是弹窗。** 之前点数据库行上的「SQL」，会盖一个浮层在页面上 —— 写 SQL
往往是个持续十分钟的事，浮层既像弹窗、又塞不下东西。现在直接进一页：

```
页头：← 返回数据库  [库名]  …………  刷新表结构
──────────────────────────────────────────────
表结构树 260px  │  SQL 编辑器（多行 + 行号 + 语法高亮）
贴左边框、全高  │  ──────────────────────────────────
               │  结果表格（虚拟滚动，吃满剩余高度）
```

**编辑器能看清语法了。** 关键字、字符串、注释各有颜色，带行号
（SQL 报错只说 "line 3"，没行号就对不上）、缩进参考线、括号自动配对。
输入 Tab 插的是两格空格，不是制表符 —— 粘到别的工具里对齐不会散。

**树更大了。** 从 220px 的浮层内区域变成 260px 全高，117 张表滚动更顺手，
搜索框仍然在（库名命中留整个库的表、表名命中只留命中的表，搜索时自动展开）。

### 顺手修的

- 结果区不再套一层外层滚动 —— 之前表头会跟着滚走，虚拟滚动也算错可见行范围。
- 「上一次执行」的回显把换行显示成 `⏎`，多行语句一眼能看出是分行的。

### 需要知道

- **多条语句仍是逐条执行**（每条约 70ms 起步），界面上写着这句话。
- 存储过程 / 触发器定义（`CREATE PROCEDURE … BEGIN … END`）这一版仍不支持：
  里面的 `;` 需要 `DELIMITER` 才能正确切分，而 `DELIMITER` 是客户端命令、
  `mysql -e` 也不认。
- 空结果集和 `SET` / DDL 的输出都是零字节，分不出来，统一显示
  「执行成功，没有返回行」。

### 依赖变化

启用 `gpui-kit` 的 `tree-sitter-sql`，新增 `tree-sitter` / `tree-sitter-json` /
`tree-sitter-language` / `tree-sitter-sequel` 四个包。
⚠️ `cc` 从 1.7.0 降到 1.2.67 —— `tree-sitter-sequel` 要求 `~1.2.1`，
而 `cc` 同 major 只能留一个版本。`embed-resource` 要的是 `^1.2`，1.2.67 满足。
