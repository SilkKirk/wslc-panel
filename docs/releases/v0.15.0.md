# v0.15.0

数据库管理从「只认 MySQL」变成**多引擎**：除了 MySQL / MariaDB，现在也能管
**PostgreSQL** 容器——SQL 控制台、表结构树、方言感知补全都通。

> 版本号从 0.12.4 跳到 0.15.0：这次是内核架构改动（数据层拆出多驱动），
> 开发过程中这两层分别标为 v0.13 / v0.14（代码注释里还能看到这两个标记），
> 合并成这一版发布。

### 怎么用

容器行上出现「数据库」按钮 → 进 SQL 控制台。MySQL 家族的按钮判定没变，
**PostgreSQL / PostGIS / TimescaleDB 的镜像现在也认**。

### 多引擎是怎么做的

参考 [dbx](https://github.com/t8y2/dbx) 的架构（只读它的设计，没抄代码）：
**引擎抽象成驱动、方言变成数据**。

- 新增 `wslc-core/src/db/`：`DbKind`（MySql / MariaDb / Postgres）、
  `DbHost`（容器 / 发行版）、`SqlDriver` trait、方言数据表
- MySQL 和 PostgreSQL 各一个驱动实现，UI 只认 `&dyn SqlDriver`
- 以后加第三个引擎（Redis / SQLite…）原则上只动 `wslc-core`

MySQL 那条代码路径**一行没改**：新引擎走独立分支，出问题可以单独回退。

### PostgreSQL 这一侧是**实测**出来的，不是照文档写的

拉了个真容器（`postgres:16`）逐项测，抓到四处会让解析器出错的差异：

| # | 项目 | `mysql -B` | `psql -A` |
|---|---|---|---|
| 1 | 默认分隔符 | TAB | **字面 `\|`** |
| 2 | 表头尾部 | 干净 | **多一行 `(N rows)`** |
| 3 | DDL 输出 | 空 | **`CREATE TABLE` 命令标签** |
| 4 | 错误格式 | `ERROR 1064 …` | `ERROR: …` + `LINE 1: …` + `^` |

第 3 条最阴：不处理的话，执行一条 `CREATE` 会被解析成**一张假表格**。

还测出一条更要命的：`psql -A` **完全不转义**值里的 tab 和换行——含 tab 的值
被切成两列、含换行的值被切成两行。而 `text` 列里带换行是常态（JSON、SQL 片段）。
所以驱动改用 `--csv`（引号规则正确）。

**意外收获**：`--csv` 模式下没有 `(N rows)` 尾行，而且**空结果集仍带表头**——
比 MySQL 的 `-B`（0 字节）强，零行也能显示列名。

完整实测记录在 `docs/postgres-measured.md`，8 个真实夹具在
`crates/wslc-core/tests/fixtures/postgres_*`。

### 方言感知

- **关键字按引擎给**：MariaDB 有 `RETURNING`，MySQL 有 `STRAIGHT_JOIN`，
  PostgreSQL 有 `ON CONFLICT` / `ILIKE` / `RETURNING`
- **标识符引号按引擎给**：MySQL 反引号、PostgreSQL 双引号
- **注释符号按引擎给**：`#` 是 MySQL 的，PostgreSQL 里写了是语法错误

### PostgreSQL 的已知边界（说在前面）

- **数据库 / 用户 / 备份恢复暂不支持**。那三块建在 `SHOW DATABASES` 的字符集、
  `mysql.user` 的 `Host` 列、`mysqldump` 的备份文件上，PostgreSQL 里要么不存在、
  要么叫别的名字。所以那一页明说支持到哪儿，并给一个真能用的入口，
  而不是画一堆点进去报错的按钮。
- 表结构树里显示的是 **schema**（`public` 等），不是库名——因为
  `information_schema` 按库隔离，一次查询只能看到一个库。
- 只支持容器里的数据库（和 MySQL 一样走 `wslc exec`）；发行版里的数据库还没接。

### 其他

- 默认用户名跟引擎走：PostgreSQL 官方镜像**没有 root 账号**，现在会预填
  `postgres`（不然第一次连接就报 `role "root" does not exist`）
- 读表结构对 PostgreSQL 要多一次查询（列信息），约 +70ms
