## 一、一个真 bug：导出 CSV **没按屏幕上的排序** ✅ 建议升

SQL 结果表格允许点列头排序。排完之后点「导出 CSV」，**文件里的行序是原始顺序**
—— 看起来就像排序没生效。

**根因**：`sql_table.rs` 里那个存储排序下标的字段，注释写得非常明确：

```rust
/// 存下标而不是重排 `rows` 本身：原数据要原样留着导出 CSV
/// （导出的顺序该跟屏幕上一致 —— 所以导出时也要读这个）。
order: Option<Vec<usize>>,
```

但 `export_sql_result_csv` 读的是 `db.sql_results[tab]` 的**原始** `rows`，
一次都没碰过 `order`。注释是对的，实现没跟上。

**为什么 CI 查不出来**：两侧的纯逻辑各自都有测试且都通过 —— `sort_order`
（排得对）、`to_csv`（转义对）。错的是**它们中间那根线没接上**，
而 `wslc-panel` 不在任何测试目标里（渲染层没有测试，见 `AGENTS.md` §8）。

**改法**：`to_csv(result, order)` 多收一个行序，`None` 保持老行为
（没排序就是原始顺序，完全兼容）。行序从 delegate 里取 —— 它和 `Shell`
共享一个 `Arc<Mutex<Option<Vec<usize>>>>`，排序时写、导出时读。

为什么用共享槽而不是"把 delegate 借出来"：delegate 藏在
`Entity<TableState<SqlResultDelegate>>` 的泛型参数后面，而 `TableState`
没有公开"借出 delegate"的接口；本机没有 gpui-kit 源码，赌一个 API 名赌错了
就是一轮 CI。

⚠️ 下标越界时**跳过**而不是 panic：`order` 来自界面状态，和结果集之间只靠
"同一个结果集"这个约定对齐 —— 对不上也不该把面板拖掉。

## 二、一个真 bug：MySQL 的 TLS 错误被说成「连不上服务器」

`wslc-db/src/my.rs` 的错误归类里有个自相矛盾的写法：

```rust
IoError(_) => DbError::new(DbErrorKind::Connect, …),   // ← 先截走
UrlError(_) => …
_ => { if text.contains("TLS") || text.contains("SSL") { Tls } … }  // ← 永远收不到
```

而**紧挨着它的注释正是**"TLS 握手失败在 mysql crate 里也走 `IoError`"。
按代码自己声明的前提，最后那条 TLS 分支**永远收不到 TLS 错误** ——
它们先被截成"连不上服务器"了。用户拿着"查网络"的提示去排证书问题。

同一类错的第二半是大小写：判据写 `contains("TLS")`（全大写），
而 `pg.rs` 那边栽的是**镜像版**（全小写，漏掉驱动的大写措辞），
v0.17.0 修过一次，注释里还留着"这是判据归一化而不是多加一个关键词"。
这边一直没跟上。

**改法**：TLS 判断挪进 `IoError` 那一支，并先 `to_lowercase()` 再比 ——
和 `pg.rs` 一致。判据拆成纯函数（`classify_server_code` / `classify_io_error`），
新增 3 条测试钉住：错误号映射、TLS 认出（5 种大小写措辞）、其余仍归 Connect。

> ⚠️ **诚实说明**：本机没有 Rust 工具链，也没有一个要求 TLS 的 MySQL 实例，
> 所以"TLS 失败到底落在哪个变体"**没有实测过**。改法是"让判断发生在两个
> 变体都覆盖到的位置"，无论哪种都成立 —— 而不是赌某一个。这条已写进注释。

## 三、三处「逐行相同」的实现收成一份

### ① 容器 / 发行版的"跑一条动作"

`spawn_container_action` 和 `spawn_distro_action` 除入参类型外**一字不差**：
发「正在…」→ 后台跑一条 CLI → 按结果发提示 → `refresh`。

抄两遍的代价不是 40 行，是**漂移**。这个仓库已经吃过一次同类的亏：
`deploy/lifecycle.rs` 里 `start` / `stop` 也是逐行同形，结果 v0.9.13 那次
`stop` 漏了 `progress` 守卫（A 跑动作时点 B 的停止会覆盖 A 的进度）。
而这两处**已经开始漂移了**：容器那份留了 7 行"点下去先给个回应"的说明，
发行版那份只有 2 行。

现在收成 `Shell::spawn_simple_action`，两个域各写一行适配闭包把签名差异吞掉。
两个旧函数保留（名字说明语义），但都缩成一行转发。

### ② MySQL 两张表的读取分叉

`load_db` 和 `reload_db_lists` 里各写了一遍同一个分叉：
**有连接串走原生、否则进容器 exec**。

两段逐行相同，而它们带着两条容易漏的约束：两条查询必须**独立**
（用户列表读不到 `mysql.user` 是常态，那时库列表不能跟着失败）、
以及有连接串**必须**走原生（否则"建完库刷新"会读容器，和页面上显示的远程库对不上）。

这两条约束原先只在 `load_db` 那份的注释里写清了 ——
而这正是 v0.16 加原生连接时差点漏掉的地方。现在只有 `read_mysql_lists` 一份。

### ③ 部署记录被逐字段抄了三遍

`submit_deploy` 里同一个 `DeployRecord` 构造了三次（站点失败 / 成功 / 启动失败），
**9 个字段一模一样**，只有 `site` 或 `members` 不同。

代价是**加字段时漏改一处** —— 而漏改的表现是"某条路径写进去的记录少了一列"，
要等用户重新部署才发现，看起来像存档坏了。改用 `..record.clone()`
之后只剩真正不同的那个字段。

## 四、其余规范类修正

- **提交型浮层的页脚不能无条件关窗**：4 个提交臂里只有 `Prompt` 写对了
  （判"状态清掉了吗"再关窗）。另三个在校验失败时会"弹窗闪一下又回来"，
  刚被送过去的焦点也丢了。已收成 `close_top_dialog_if_closed`。
- **`shell/core.rs` 里堆着只属于单域的助手**：`effective_db_creds`、
  `PreparedDbSql`、`leaf_id`/`folder_id`/`TREE_ID_SEP`、`confirm_body`
  全在"每个域都会用"的那一层，但各自只有一个调用点。逐个搬到唯一的调用点旁边。
  顺带修掉一个真隐患：`TREE_ID_SEP` 拼的时候用常量、拆的时候用字面量
  `'\u{1}'` —— 改一边就是"点了没反应"，且没有任何编译错误。
- **`explorer.exe` 起了四份一模一样的壳** → 收成 `reveal_with_explorer`。
- **两个零调用点的 `pub fn`**（`mirrors::available_on_this_arch`、
  `cmd::network::attachable_names`）→ 删掉。`AGENTS.md` §5 的判据：
  接口应当等于真实的使用面。
- **README 写着一个已不存在的功能**：「终止会话」被列进"全部走二次确认"的动作里，
  但 v0.9.16 就删掉了会话列表采集 —— 界面上没有那个按钮。
- **`views/` 里四个裸 `pub`** → `pub(crate)`（这是 bin crate，裸 `pub` 是个假信号）。
- **`blocks.rs` 的 `common::*`** → 逐项导入（全仓唯一一处 glob，实际只用到 2 项）。
- **两处测试条数与实现不符**（`sqlcomplete` 写 17 实为 16）。

## 需要你实机确认的（CI 覆盖不到）

CI 只证明**编译过 + 纯逻辑测试过 + 格式干净**。下面三项本机没有工具链 / GPU，
**没有验证过**：

1. **SQL 结果表格排序后导出 CSV**，确认文件顺序与屏幕一致（本版主修复）；
2. **四种浮层的校验失败路径**（部署 / 创建容器 / 数据库动作），
   确认弹窗留在原地而不是闪一下；
3. **数据库连接失败的提示**，确认仍是"连不上"而非误报 TLS。
