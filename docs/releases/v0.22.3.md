# v0.22.3 —— 一次全仓审查：1 个真 bug + 8 组"同一条规则几份实现"

这一版**没有新功能**。它来自一次按 `AGENTS.md` 逐条比对的全仓审查
（4 个 crate / 187 个 `.rs` / 约 65 000 行）。

改的都是"代码自己和自己不一致"的地方 —— 而那些恰恰是最难查的一类：
不会有编译错误，界面上也未必看得出来，但下次谁改到它就会踩。

---

## 一、一个真 bug：PostgreSQL 下「点表名」不能用 ✅ 建议升

SQL 控制台左边那棵库／表树，**点一下表名**会把 `SELECT * FROM …` 填进编辑区。
在 MySQL 上一向没问题，在 **PostgreSQL 上填进去的却是**：

```sql
SELECT * FROM `public`.`t_user` LIMIT 200
```

反引号在 PostgreSQL 里是**语法错误** —— 于是"点表"这个动作等于点了没反应
（填进去了，但跑不了）。

**根因**不是漏了一个分支，而是拼 SQL 的规则有**两份手写实现**：
`model::schematree` 一份写死反引号（MySQL）、`model::postgres` 一份写死双引号。
而控制台点树时**一律**走 MySQL 那份，pg 那份从来没被调用过。

现在拼法只有一份，在 `DialectData::select_from_table_sql`（方言层本来就有
`quote_ident` / `limit_clause`，只是没人用它拼过完整 SQL）。调用点按
`dialect_for(db.conn.kind)` 取当前引擎的方言。

> 这个 bug 在 v0.14 加 PostgreSQL 支持时就有了。受影响的只是「点树里的表名」
> 这一个入口 —— 手写 SQL、点「执行」都不受影响。

## 二、八组「同一条规则写了好几遍」

审查时按"同一条规则只该有一份实现"逐组核，收掉 8 组。挑三组说说为什么值得改：

### ① 两个存档：写盘失败会把**整份存档清空**

`dbcreds.json`（数据库账号）和 `deployments.json`（部署记录）的 `save` 都写着：

```rust
let text = serde_json::to_string_pretty(self).unwrap_or_else(|_| "{}".to_owned());
```

也就是"序列化不了就把整份存档覆盖成 `{}`"，而且函数返回 `Ok`。
兜底方向反了 —— 兜底该往"保住旧数据"倒，不该往"清空"倒。

实际到不了这条路（字段都是扁平的 `String` / `u16` / `Vec`），但方向错了就该改。
现在序列化失败返回 `Err`，用户会看到一句"写凭据存档失败：…"。

顺带把三个存档（含 `prefs.json` 那份第三套写法）的读／写收进
`fileio::read_json` / `write_json`，兜底语义只有一份。

### ② `-q`：注释承诺"必须放最前"，代码不保证

`curl.exe` 的公共入口注释写着「`-q` **必须**放在最前」（不读用户的
`_curlrc` —— 那里面的 `--proxy` / `--output` 能改请求目的地和落盘位置），
但代码是"调用方已经带了就不重复加"，**没保证它在最前**。

目前所有调用方碰巧都不带，所以行为是对的 —— 但这是靠约定，不是靠结构。
现在**永远**先塞一个 `-q`，再把调用方那些滤掉，并有测试钉住
"最前 + 只一份"（4 种形状：不带 / 在中间 / 在最后 / 空参数）。

### ③ 短 ID：同一句抄了四遍，解释只写在一处

容器（×2）、镜像、网络四个模型的 `short_id()` 是逐字相同的
`self.id.get(..len.min(12)).unwrap_or(&self.id)`，
而"为什么用 `get` 不用 `&s[..12]`"这段护栏说明**只在 container.rs 写了**。

（`&s[..12]` 在 id 含多字节字符、第 12 个字节落在字符中间时会 **panic**。）

收进 `util::short_prefix`，并加了 3 条测试，其中一条直接拿
`"abcdefghijk中"` 钉住"非字符边界退回整串"—— 那条输入上 `&s[..12]` 会崩。

### 全部八组一览

上面细说了三组（存档读写、`-q`、短 ID），这里是完整清单 ——
"原先几份"是收口**之前**各写一遍的数量：

| 收成什么 | 原先几份 | 细说在 |
|---|---|---|
| `fileio::{read_json, write_json}` | 3（另有一份写法不同） | 上面 ① |
| `cmd::http::with_quiet_first` | 2（注释 vs 代码） | 上面 ② |
| `util::short_prefix` | 4 | 上面 ③ |
| `DialectData::select_from_table_sql` | 2 | 第一节那个 bug |
| `model::deploy::{normalize_target, is_under, first_segment_under}` | 2（跨 crate 逐字节相同） | — |
| `mirrors::is_http_url`（`open_url` 不再手写） | 2 | 第四节 |
| `DashboardStats::container_percent` | 2 | — |
| `mysql::{CHARSET_LABEL, COLLATION_LABEL}` | 2 | — |

## 三、界面层：75 个 `pub(crate)` 在"骗人"

`views/` 下有 **75 个 `pub(crate) fn/const` 在别的文件一次都没被调用过**
（不算注释里的提及）。`dashboard.rs` 尤其极端：9 个 `pub(crate)`、0 个私有项。

`pub(crate)` 的意思是"别处会用"，读代码的人据此判断"改它要小心谁" ——
而实际上一个调用方都没有。现在这 75 个改回私有（**纯可见性改动，0 行行为变化**），
`views/` 剩下的 `pub(crate) fn/const` 是 72 个。

> 这一条对使用者的影响是 0，写在这里是因为它解释了这个版本为什么有一批
> "看起来什么都没改"的提交（`9193d4d`：18 个文件，80 增 / 75 删，
> 每一行都是 `pub(crate)` 去掉或签名随之折行）。

## 四、顺手修的

- `open_url` 手写的 `starts_with("http://")` 换成 `mirrors::is_http_url` ——
  手写版**区分大小写**，`HTTPS://example.com` 在镜像探测那里能过、
  点「打开」却报"不是可打开的 URL"；
- 两处 `#[allow(dead_code)]` 的注释是错的（都写着"只有测试按名字用"，
  实际都在正式路径上被调用）—— 多余的 allow 会让真死代码永远不报警；
- `wslc-core/src/lib.rs` 里 `truncate_chars` 被一个制表符吃掉了首字母；
- `AGENTS.md` 两处描述与实现不符（加新浮层并不需要动 `sync_dialog_stack` 的
  `if` —— 那个 `if` 早在改成 `DialogKey::ALL` 表时就不存在了）。

## 六、需要你知道的

- **版本号之外的依赖没变** —— `Cargo.lock` 只改了四个成员的 `version`，
  一个第三方 crate 都没动；
- 这一轮**有一个提交红过又修好**：`with_quiet_first` 一度写成
  `Vec<String>`（`run_helper_with_hint` 收的是 `&[&str]`），CI 的
  `error[E0308]` 抓出来之后改回 `Vec<&str>`。最终 `main` 是绿的。
- **界面渲染没在本机验证过**（这台机器没有 Rust 工具链，CI 只做 `cargo check`）。
  75 处可见性降级理论上不影响渲染（改的是 `fn` 前面的 `pub(crate)`），
  但如果哪里出现"某个界面元素不见了"，那是本次最可疑的改动。
