# v0.17.0 —— 依赖大版本升级

这一版**没有新功能**，全部是底层升级。按你的要求"全都升级到最新"，逐个清点了
所有直接依赖和锁文件里能升的包。

---

## 升了什么

### ① GPUI 栈：0.7.1 → 0.8.0

| | 之前 | 现在 |
|---|---|---|
| `gpui-kit` | 0.7.1 | **0.8.0** |
| `gpui-base` / `gpui-component` / `gpui-kit-assets` | 0.7.1 | **0.8.0** |
| `gpui-pre` 全系（18 个包） | 0.3.8 | **0.3.9** |

**零代码改动**——0.8.0 的 17 条 breaking change 里，我们只命中一条
（Linux 的启动方式），而这个项目只出 Windows 包。

顺带的好处：锁文件从 **776 个包减到 735**（−41）。0.8.0 把 `gpui-fast`
改成可选，不再默认拉进来，于是 `bindgen`、`clang-sys`、`bzip2`、
`async-compression`、整个 `sval` + `value-bag` 家族都消失了 ——
**安装包更小、CI 冷缓存更快**。

### ② Rust 版本：workspace 统一到 1.85 / edition 2024

`wslc-core` 原来是 `edition 2021` + MSRV **1.75**，现在统一成 `2024` / **1.85**。

**为什么提上去**：那个 1.75 承诺**从来没被验证过** —— CI 一直用浮动的
`stable`（现在实际是 1.99），没有任何一个 job 真的用 1.75 编译过它。
而 `gpui-kit` 0.8.0 全系是 `edition = "2024"`（我核了它仓库根的
`Cargo.toml`），下限就是 1.85。

留着一个没人核对的版本声明，比统一成一个真的数字更糟。

## 两个**刻意没升**的

**① `cc` 停在 1.2.67。** `tree-sitter-sequel`（SQL 语法高亮）要求 `~1.2.1`
（只认 1.2.x），而 `embed-resource` 要 `^1.2`。同一个 major 只能留一个版本，
取交集就是 1.2.x。

**② `tree-sitter` 停在 0.26.13。** 0.27 要求 **Rust 1.90**，而 `gpui-component`
只认 `^0.26.13`。硬升会把整个项目的 MSRV 抬到 1.90，收益为零。

## ⚠️ 装上后请重点看这三处

这一版**所有改动都只证明了"能编译"**。0.8.0 有两处改了运行时行为，
而我们的界面**没有渲染测试**：

1. **表格列宽 / 列顺序** —— `DataTable` 的默认列宽上限改成了 1200px，
   `set_selected_row` 不再阻止事件传播。三张表（容器 / 镜像 / 发行版）都用它。
2. **表结构树的点击** —— `Tree` 的选择从 mouse-down 改成了 **click**。
   SQL 控制台左边那棵树用它，点一下应该能选中、点箭头展开。
3. **侧边栏折叠 / 弹窗遮罩 / 动画** —— 这些也走组件库，看一眼有没有走样。

如果哪里不对，**回退路径很干净**：`gpui-kit` 改回 0.7.1 + 重新 gen-lock
即可，不影响数据库那些改动。

## 顺带补的工具缺口

`gen-lock` 工作流原来只能走 `cargo metadata`（**最小更新**：只补缺口，
绝不抬高已锁定的包）。所以 `tokio 1.53 → 1.54` 这类更新**原本没有任何入口**，
而手改 `Cargo.lock` 又会因传递依赖变化必然出错。

现在它支持一个可选输入：

```
workflow_dispatch
  update: 'tokio,serde_json,rustls,libc'   # 留空 = 保持原来的最小更新
```

以后升级补丁版本走这个入口。
