# v0.16.1 —— 两个实机反馈的修复

v0.16.0 装上后反馈的两个问题，都是"看起来小事、用起来很碍事"的那种。

---

## ① 连接卡的账号会自己变

**现象**（原话）：

> 在这个列表页面一直都是 root 啊，进 sql 界面才是对应的数据库和 djxm 角色，
> 然后退出来这个列表界面变成了 djxm 了，这个不对吧

**原因**：点列表某一行的「SQL」时，面板会把**那一行的账号**写进连接卡
（「基础信息」里那两格）—— 查那个库确实该用它，但那张卡是**整页共享**的，
而退出时没有还原。

后果不止"看着不对"：退出之后，「数据库管理」页的每一个动作（读用户列表 /
新建库 / 备份）都在用业务账号跑，于是拿到 `ERROR 1142`。

**现在的行为**（也是更对的设计）：

| | 之前 | 现在 |
|---|---|---|
| 连接卡（基础信息） | 会在 root 和 `djxm_user` 之间跳 | **永远是 root**（你填什么就是什么） |
| 点某库的「SQL」 | 改卡，全局生效 | 只影响这个库，卡不动 |
| 谁在查这个库 | 看不出来 | SQL 页头写明 `账号 djxm_user（这个库的）` |

执行时本来就是按行取账号（面板给这个库记过账号就用它，没记过才退回卡上那个），
所以"改卡"这一步从头到尾都是多余的。

「备份」浮层有同一个问题，一起修了。

## ② 用户列表的权限错误糊住了整页

**现象**：用一个普通账号进数据库页，「用户」那条查询被拒（`ERROR 1142`，
读不到 `mysql.user`），于是**整页顶上挂着一条红色横幅** ——
而「数据库」tab 明明好好地列着库和表。

**现在**：

- 红卡片只画在「用户」tab 里，并给一句能操作的话：去「基础信息」换成高权限账号；
- 「用户」标签变成 `用户（读取失败）`，你知道点进去会看到什么；
- 换账号重读成功后标记自动消失。

说实话：`ERROR 1142` 本身是**正确行为**（普通账号读不了 `mysql.user`，
这是 MySQL 的权限设计），之前只是**报错的方式**不对。

## 这两条现在都有测试守着

```
test state::tests::a_users_query_failure_never_becomes_a_page_level_error ... ok
```

断言：`users_error` 有值、整页 `error` 仍为空、页面仍 `usable()`、清掉后标记消失。

方法放在 `wslc-panel-core`（**能跑测试的 crate**）而不是 `wslc-panel` ——
后者不在任何测试目标里，写那边的断言永远不会执行。将来谁觉得"错误应该统一处理"
又把用户失败塞回 `error`，这条会立刻炸。

## 没变的部分

v0.16.0 的其余行为不变：连接串（`postgres://…` / `mysql://…`）、原生连接、
表结构树、TLS 未支持（会明确报错，不静默降级）。
