# v0.10.4

一次审查修复批次。**数据库页的账号来源统一了**，**安装包终于带上了我们的图标**，
删除备份改成先确认。

### 修复

- **数据库页：行内动作按「这一行」取账号。**
  面板给某个库记过账号（建库时同时建的那个用户，如 `djxm` → `djxm_user`），
  那这一行的备份 / 导入 / SQL / 删除 / 恢复全用它；没记过的库才退回
  「基础信息」卡上那份。

  之前是两套来源混用 —— 典型症状：点 `djxm` 那行的「备份」（卡被换成
  `djxm_user`），再在同一个浮层里点「恢复」，会拿 **root** 去恢复，
  报 `Access denied`，而浮层上明明写着 `djxm_user`。

  备份浮层顶部那句账号说明也跟着改了：现在显示的是**实际会用的账号**，
  而不是卡上碰巧是什么。

- **安装包现在真的有图标了。**
  `SetupIconFile` 那几行**从没进过仓库主干**（v0.10.0 ~ v0.10.3 四个版本的
  安装包用的都是 Inno 默认图标，而 v0.10.1 的说明写着"安装包也有图标了"）。
  核对方式：下载 v0.10.3 的 setup，13 张图标与 `assets/wslc-panel.ico` 的
  7 张**零重合**。

  根因是校验脚本只判"有没有图标资源"，而 Inno 的默认图标也满足那个判据。
  现在它按 sha256 真的比对图标**内容**，发布流水线也会对安装包跑一遍 ——
  下次这种东西进不了发布。

- **删除备份文件先确认。** 之前正好反着：「恢复」（覆盖数据，但旧库还能再
  备份）有确认，「删除」（Windows 侧文件 + 容器内一起删，删了就没了）反而
  直接执行。确认框里会把**两份路径**都写出来，并说明"数据库本身不受影响"。

- **更新检查失败也记节流时间。** 原先只在成功时记录，于是网络不通的机器
  **每次启动都重发一次请求**（最长 25 秒），和"24 小时最多一次"的说法相反。

### 改进

- **备份 / 导入浮层可以「放到后台」。** 导入浮层原先一个按钮都没有，而它
  带遮罩挡住整页 —— 导一个大 dump 时用户只能干等，连"去看看容器是不是挂了"
  都点不到。收起不取消，页头会留一行「正在备份 X…」。
- **备份目录扫描挪出界面线程。** 进数据库页 / 备份完成 / 删除完成后会重扫
  备份目录，原先那一下在界面线程上做（机械盘或备份多了会卡帧）。

### 其它

- 补了 5 处 Markdown 标记没清干净的文案（添加实例的步骤说明、设置页「终端」
  的第一段、`.wslconfig` 的提示、创建容器的变量提示、日志浮层的空状态）。
- 两处"先判一遍、再 unwrap 一次"的写法改成单次取值（`settings.yaml` 的写入、
  `wsl -l -v` 的解析）—— 这类写法安全靠"上一段的记忆"，重构时容易被带歪。
- 修掉三处**注释和实现相反**的地方（镜像页说行内只剩「更多」而实际是两个
  直接按钮；说某字段没人读而实际已在读；说资源编译失败会静默降级而实际会 panic）。

### 需要实机确认

- 三个浮层的「放到后台」：收起后页头应该还在说"正在备份 / 导入…"。
- 备份列表里的「删除」现在会先弹确认框。
- 数据库页点 `djxm` 那行的「备份」→「恢复」，应该用 `djxm_user` 而不是 root。
