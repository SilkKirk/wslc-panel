# v0.12.4

SQL 编辑器有了**方言感知的自动补全**；「执行」换到编辑区左侧（挨着代码）。

### 自动补全

参考 [dbx](https://github.com/t8y2/dbx) 的做法，三档候选都做了：

1. **关键字按方言给** —— 连的是 MariaDB 就有 `RETURNING` / `NEXT VALUE FOR`，
   是 MySQL 就有 `STRAIGHT_JOIN` / `ON DUPLICATE KEY UPDATE`。
   通用的语句骨架（`SELECT` / `FROM` / `WHERE` …）两边都有。
2. **对象名** —— 库、表、列，来自 `information_schema`。
   补出来的表名带库名（`djxm.sys_user`），因为控制台可能没指定当前库，
   裸表名会报 "No database selected"。
3. **上下文** —— 这条才是关键：
   - `FROM ` / `JOIN ` / `INTO ` 后面**只给表**（这时候给你一堆 `SELECT`
     反而碍事）；
   - 打了 `别名.` 之后**只给那张表的列**，别名是从 `FROM t [AS] a` 里推的；
   - 打了 `库.` 之后给该库的表；
   - **认不出的前缀什么都不给** —— 打了 `x.` 却给一堆关键字，
     补完会变成 `SELECT.foo`，比不补更糟。

### 键盘行为

打字时（字母 / 数字 / `_` / `.` / 反引号）自动弹；空格、逗号、`)`、`;`
不弹 —— 那些位置你刚写完一个表达式，弹菜单只会挡住结果。

### 布局

「执行」移到编辑区左上、紧挨代码；「当前库 / 改为不指定」移到右边。
按你的要求换的：眼睛从代码往下扫，第一站应该是执行。

### 代价

读表结构现在要**两条查询**（表 + 列），多约 70ms。
列读失败不影响树本身，只是补全少一档候选。

### 已知限制

补全不做语法分析，所以：

- `WITH x AS (...) SELECT * FROM x` 里敲 `x.` 补不出列（`x` 不是真表）；
- 子查询里的别名、同名表在多个库出现时按第一个匹配。

它的失败方式是"那一档候选不给"，而不是"给错候选"。

### 需要你验的

- 打字时补全菜单弹不弹、候选对不对；
- `FROM ` 后面是不是只有表；
- `别名.` 之后是不是只有那个表的列；
- 中文表名 / 列名能不能补出来。
