### 判据 1 的现成实现

```powershell
$panel = (Get-ChildItem -Recurse -Filter *.rs crates\wslc-panel\src).FullName
foreach ($f in $panel) {
  $ls = [System.IO.File]::ReadAllLines($f)
  for ($i=0; $i -lt $ls.Count; $i++) {
    if ($ls[$i] -match 'overflow_[xy]_scroll\(\)') {
      $s = [Math]::Max(0, $i-8)
      if (($ls[$s..$i] -join "`n") -notmatch '\.id\(') {

      }
    }
  }
```

### 判据 7 的两个已知误报

"零引用"的常见假阳性，**不要照着删**：

- **类型推断用法**：`let caps: X = f();` 之后 `caps.field` —— 名字只出现在
  定义处和字段访问处，粗扫会判成没人用；
- **只被测试按名字用**：那种要三件套（`#[allow(dead_code)]` + `pub(crate) fn`
  + `#[cfg(test)] pub(crate) use`），见 `AGENTS.md` §2 第 7 条。

真删除之前必须逐个确认"连测试都没提过"。

## 二、只能人工读的（跑不出来）

这一节才是审查真正花时间的地方。2026-10-28 那轮抓到**两个真 bug**，
都出在这里。

### 1. 注释与实现是否一致

**判据**：看到"**所以 X 时也要 Y**""**导出时要读这个**"这类句子，
就去 X 的代码路径上确认 Y 真的发生了。

实测抓到：

| 位置 | 注释说 | 实现 | 后果 |
|---|---|---|---|
| `sql_table.rs` 的 `order` 字段 | "导出的顺序该跟屏幕上一致 —— 所以导出时也要读这个" | `export_sql_result_csv` 读的是原始 `rows`，一次没碰过 `order` | 点列头排序后导出，得到一份**看起来没排过**的 CSV |
| `wslc-db/src/my.rs` 的 `classify` | "TLS 握手失败在 mysql crate 里也走 `IoError`" | TLS 判断写在最后的 `_ =>` 里，而 `IoError(_) => Connect` 先把它截走了 | TLS 失败被说成"连不上服务器"，用户去查网络 |

两条都是"注释是对的、实现没跟上" —— 而注释写得越肯定，后来的人越不会去核。

### 2. 同一件事在两处写法不同

**判据**：同一个判据出现两次以上时，**跨文件比对**写法。

实测抓到：`pg.rs` v0.17.0 修过 `contains("tls")` 的大小写问题
（注释里还留着"这是判据归一化而不是多加一个关键词"），
而 `my.rs` 一直是镜像版的全大写 `contains("TLS")` —— 改一处忘一处。
现在两边都先 `to_lowercase()`。

同类值得定期比对的有：

- `pg.rs` / `my.rs` 的错误归类（错误号 → `DbErrorKind`）；
- 各域的 `spawn_*` 包装（超时、取消、事后刷新是否一致）；
- `classify` / `explain_*` 这类"把错误翻成人话"的函数。

## 四、界面/展示层的判据（2026-10-30 补）

这些**跑不出来**，只能一页一页读。但它们有明确的"对错"，所以能列成清单 ——
每一条都是这一轮实际抓到问题的类型。

### 1. 空态有没有说"下一步点哪"

**判据**：这个页面**有**创建/刷新入口，空态却只说"没有 X" → 该改。

正例（已经对的）：

| 位置 | 文案 |
|---|---|
| 数据库页 | `还没有读到数据 —— 点右上角「重新读取」` |
| 备份浮层 | `还没有备份 —— 点右上角的「立即备份」生成第一份` |
| 容器页（筛选后为空） | `没有匹配的容器` + `换个关键词，或点「全部」；也可以清空筛选。` + 一个「清空筛选」按钮 |

反例（这一轮改的）：镜像页原写 `没有本地镜像`、卷页原写
`没有卷（无卷时 wslc 输出为空）` —— 两页页头都有创建入口。卷页括号里那句
尤其要改：它是**给开发者看的**（解释为什么这个列表会空），不是给用户的下一步。

⚠️ **反例中的反例：网络页**。它**没有**创建入口（面板没接
`wslc network create`），所以那里只该说"为什么会空"，不该编一个不存在的
"点这里"。**别把这条规矩机械地套到所有页面** —— 前提是那个页面真的有下一步。

### 2. 行内按钮的 id 用业务标识，不用下标

**判据**：`enumerate()` 拿到的 `ix` 拼进 `id` → 改。

GPUI 的 hover / 焦点状态**按元素 id 记**。删掉上面一行之后，下面各行的 id
整体前移，光标停的那一行会忽然变成另一行。全仓现在都用业务标识
（容器名 / 库名 / 应用名 / 卷名 / 网络名）。

这一轮改掉了网络页和卷页（最后两处用下标的）。

### 3. 同一张表里的布尔列，措辞一致

**判据**：同一张表里出现 `启用/关闭` 和 `是/否` 两种 → 挑一种。

网络页的 `IPv4` / `IPv6` 原写 `启用/关闭`、`内部` 写 `是/否` —— 三列列头都是
名词、回答的都是"有没有/是不是"，两种措辞会让人以为它们不是一回事。

### 4. 不要用空 `div` 当间距器

**判据**：`div().h(px(n))` 出现在 `v_flex`/`h_flex` 的子项里当间隔 → 改成分组 + `gap_*`。

理由不是丑，是**不可组合**：调外层 `gap` 时它不跟着变，间距变成
"8 + 4 + 8"这种没人记得住的数，而这数只存在于那一屏的视觉记忆里。

### 5. 注释里列的顺序要和代码一致

**判据**：文档写"底部那排数字：A / B / C / D"，而实际调用顺序是 B / C / D / A → 改。

`dashboard.rs` 的 `overview_tiles` 就是这一条（写着"镜像/网络/卷/WSL 实例"，
实际是"WSL 实例/镜像/网络/卷"）。**顺序本身往往是有意的** —— 不只改字，
还要写清为什么是这个顺序。

### 6. 手写组件的地方，要么改要么写清为什么

**判据**：同一排按钮/同一类信息，别处都走 `common::*` 助手，这里手写 → 查有没有真差异。

有真差异（如「编辑配置」需要 tooltip，而 `overlay_button` 没有这个参数）
就在原地写清；没有就改用助手。**不写理由的手写，下一轮会被当成漏改** ——
这条和 `AGENTS.md` §5 的"注释和实现不一致时后来人会照错的走"是同一件事。

## 五、⚠️ 走 API 推送前，必须先确认工作区是 LF

`scripts/gh-api-push.ps1` 按**工作区字节**建 blob（它必须这样：那条路是为
`github.com:443` 不通准备的，拿不到索引树）。而 Windows 检出时工作区是
**CRLF**，`.gitattributes` 的 `eol=lf` 只在 git 走索引那一步生效 ——
**API 那条路绕过了它**。

实测（2026-10-30）：一次 API 推送把两个文件推成了全 CRLF ——
`images.rs` 从 17677 字节/全 LF 变成 18508 字节/全 CRLF。后果不是"看起来
一样就行"：下次正常 checkout 时 git 会按 LF 重写，表现为**整文件的伪改动**，
正是 `AGENTS.md` §7.6 里 `--renormalize` 那条警告的镜像情形。

**推送前的一句判据**（纯本地，不走网络）：

```powershell
# 工作区字节 == 索引里的 blob？相等才说明行尾已经归一化
git hash-object --no-filters <文件>   # 对比 git rev-parse HEAD:<文件>
```

不等就先转 LF 再推：

```powershell
$t = [System.IO.File]::ReadAllText($f)
[System.IO.File]::WriteAllText($f, $t -replace "`r`n", "`n")
```

推完再验一次远端（`contents?ref=<sha>` → base64 解出来数 CRLF/LF）。
