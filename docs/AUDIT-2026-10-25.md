### 1.3 弹窗底部按钮行 —— ✅ **已修 4 处；「取消 / 关闭」那条判断已撤销**

`h_flex().w_full().justify_end().gap_2()` 这一行在 4 个弹窗里逐字相同
（`db_dialogs` 建库/建用户、`overlays` 提示输入、`deploy` 添加部署、`deploy` 删除部署），
已收成 `common::modal_footer([cancel, confirm])`。

签名是 `impl IntoIterator<Item = impl IntoElement>` —— 调用点**不用**先
`into_any_element()`（那样反而比原来更长，抽这一层就没意义了）。

**另外 14 处 `justify_end` 刻意没套**：它们要么行里混着状态文字
（"备份中… / 导入中…" + 关闭，用 `items_center + gap_3`），要么是"一行纯按钮但只有
一颗"，套进 `modal_footer` 只会多一层括号。

#### ⚠️ 原判「「取消」和「关闭」是同一个动作的两个词，要统一」—— **这条是错的**

逐处核过之后：`取消` 的 6 处全在**有提交动作、点了什么都不保存**的弹窗
（创建容器 / 添加部署 / 删除部署 / 提示输入 / wsl.conf / 建库建用户）；
`关闭` 的 9 处全在**只读浮层、本来就没有提交**（日志 / exec / 容器详情 /
发行版详情 / 备份列表 / 基础信息 / 拉取镜像 / 站点配置）。

**两者是语义不同的两件事**，统一成一个词会丢信息。这条结论已经写进
`modal_footer` 的注释里，防止下一轮又有人来"统一"它。

（留下来的备忘：`AGENTS.md` §5「同一个动作只给一个入口」讲的是**入口**，
不是**用词**。同一个动作该只用一个词，但"取消表单"和"关掉只读浮层"
本来就不是同一个动作。）

### 1.4 "选中态 = `.primary()` 按钮组" —— ✅ **已修 6 处，另 3 处刻意保留**

原先的写法是"一排 `Button`，选中那颗改成 `.primary()`"。它在**语义**上是错的：
对读屏软件来说那是一堆各自独立的**动作**，不是"这组里选了哪个"；
键盘上也拿不到官方 `Radio` 的"方向键在组内移动 + 空格选中"。

**已换（6 处）**，统一走 `common::radio_row(id, labels, selected, entity, pick)`：

| 位置 | 选项 |
|---|---|
| 设置页 主题卡 | 跟随系统 / 深色 / 浅色 |
| 设置页 刷新间隔 | 1 / 3 / 5 / 10 / 30 秒 |
| 设置页 终端起始目录 | 家目录 / 面板所在目录 / 自定义路径… |
| 创建容器 拉取策略 | 只用本地镜像 / 缺了就拉 / 总是拉取 |
| 建库弹窗 授权级别 | 三种 GRANT |
| 添加实例 安装来源 | 本地文件 / 在线（商店） / 镜像源 |

核过 `src/radio.rs`（0.8.0）后写进 `radio_row` 注释的两条约束：

1. `RadioGroup::new` 的默认 style 带 **`.flex_1()`** —— 丢进 `v_flex` 会被竖向拉长
   （和 `Field` 同一个坑），所以显式 `.flex_none()` 盖掉（`refine_style` 在 render 末尾）；
2. 横向布局在 render 里是 `h_flex().w_full().flex_wrap()` + **固定 `gap_3()`**，
   改不了 —— 所以它只适合"独占一行的一组选项"，**不适合塞进紧凑工具栏**。

**刻意没换的 3 处**（都在注释里写了理由）：

- `containers.rs` 的**筛选 chip**：那是"带计数的筛选器"、混在工具栏里，
  `RadioGroup` 横向强制 `w_full` 会把工具栏撑坏；
- `sql.rs` 的**多结果 tab**：tab 语义，不是单选；
- `settings.rs` 更新卡的 `check = check.primary()`：核过代码，那**不是选择组** ——
  只是把"检查更新"标成主按钮。原清单把它算进 9 处是数错了。

⚠️ 顺带记一笔：原清单里"`settings.rs:245` 是布尔项、该用 `Switch`"这条**也不成立**，
原因同上（它根本不是状态开关）。

### 2.1 官方 `Dialog` 替代 18 处手写模态（**最大的一块**）

已核实的公开 API（`struct.Dialog`）：`new`、`title`、`content`、`footer`、`child`、
`button_props`、`close_button`、`on_ok`、`on_cancel`、`on_close`、`overlay`、
`overlay_closable`、`trigger`、`width`、`entrance`、`keyboard`。

**为什么值得换**：
- 我们 18 个模态的遮罩（`.occlude()`）、入场动画（`with_animation` + 手工稳定 id）、
  层序（`render.rs` 末尾那条手工链子）**都是自己维护的**，而且都**踩过坑**
  （`AGENTS.md` §7.5：遮罩漏 `occlude` → 点穿 8 个弹窗；确认框被详情浮层盖住 → 实机报"压缩磁盘的确认框在详情之下"）。
- `Dialog` 自带 `overlay_closable` / `on_cancel` / `keyboard` —— 这三样我们**现在没有**：
  点遮罩不关窗、Esc 不一定关、也没有统一的取消语义。

**必须先 spike 的三件事**（**不要直接铺开**）：
1. `Dialog` 是**内联元素**（当成 `AnyElement` 塞进 `Shell::render` 的链子）还是要走某个
   "dialog 栈"（Root 上托管）？—— 0.8.0 的 `all.html` 里**没有任何**公开的自由函数
   （`open_dialog` 之类**不存在**），所以大概率是内联元素 + `trigger`/受控开关。
2. 若是栈式托管，**反而是一笔大赚**：§7.5 那条"层序靠 `.child()` 的先后手工维持"就消失了。
3. 我们的模态有 `max_h` + 内部滚动（日志/详情/表格），`Dialog` 的 `content` 是否给滚动空间。

**结论**：这是**唯一一个建议先写 spike 再动的项**。若 spike 通过，一次性能删掉
`modal_scrim`/`modal_card`/`ModalSize`/入场动画 id 管理/层序注释 5 套手工机制。

### 2.2 官方 `Accordion` 替代 `disclosure`

`Accordion` 有 `item`、`on_toggle_click`、`disabled`、尺寸档；`AccordionItem` 是"一项"。
现在的 `disclosure`（`common.rs:38`）用 `Collapsible` + 手画 trigger，
注释里写着"和 `Accordion` 的 trigger 完全一致（读 `accordion.rs` 确认过它的写法）"——
**既然已经在模仿它，就该直接用它**。`AppState` 的 `section_open(UiSection)` 折叠状态要接到
`AccordionItem::open` 上（受控）。
**风险**：中（折叠状态是我们自己的 `BTreeSet<UiSection>`，要确认受控 API）。
**验证**：实机点 4 个页面的折叠区，看箭头方向与展开动画。

### 2.3 官方 `Tooltip` —— 可能能删掉那个 Button hack

`common::cell_full` 的注释说"tooltip 那一套在 gpui-kit 里是 `pub(crate)` 的，
只有它自己的控件能挂" —— **这条在 0.8.0 可能已经不成立**：docs.rs 上
`tooltip::{Tooltip, TooltipDefaults}` 是**公开**的，方法有 `build`、`element`、`action`、`key_binding`。
**待核实**：`Tooltip` 是"包一层元素"（能包我们自己画的 `div`）还是只能配合组件库控件。
- 若能包任意元素 → `cell_full`/`cell_link` 退回成纯 `div` + `Tooltip`，**少一层 `Button`**，
  hover 状态也不会再和 `Button` 的 id 抢。
- 若不能 → 现状保留，但把 `AGENTS.md` §7.5 那条说明**改准**（现在写的是 0.7.1 的结论）。
**风险**：低（不改就维持现状）。**验证**：实机悬停 5 个表格单元格看 tooltip 出不出来。

### 2.4 `Badge` vs `Tag::custom` —— **结论：已经是官方，不用改**

原判"`Badge` 没自定义三色会丢状态信息"——**核过之后理由要换**：

- 官方 `Badge` **不是文字胶囊**，是**数字 / 红点 / 图标角标**
  （`Badge::new().count(n)` / `.dot()` / `.icon(..)`，`color()` 只设背景），
  典型用法是"消息数 3"。我们的「运行中 / 已退出」是**文字胶囊**，语义不同。
- 文字胶囊的官方组件就是 **`Tag`**，而 `common::badge` 用的正是
  `Tag::custom(bg, fg, border)` —— **官方 API 的官方用法**，不是自造。

**所以这一条不需要改动。** 唯一可选的"更标准"是改用 `Tag::success()` /
`Tag::danger()` / `Tag::warning()` 这类语义变体，但那会把配色交给组件主题
（`theme::state_colors()` 是**不透明预置色**，容器状态有 6~7 档，映射到 4 个
语义变体会**丢信息**，而且与 `theme.rs` 自己那套调色板冲突）。

⚠️ 结论要写进注释的那句话因此改成："**文字胶囊用官方 `Tag::custom`；
数字/红点角标才用 `Badge`**"——这是两个组件，别互相替代。

### 2.5 `Form` / `Field` —— ✅ **已换 `Field`（外壳）**

官方 `form` 模块给的是**布局容器**，不是校验框架（原判"等于重写 8 个表单的校验"
说得过重）。核过 `src/form/field.rs` 的源码，API 与取舍：

| 组件 | 方法 | 和我们 `form_field` 的关系 |
|---|---|---|
| `Form` | `new()`（单列、**标签在上**）、`horizontal()`、`vertical()`、`layout(Axis)`、`label_width(Pixels)`（默认 `px(140.)`）、`child(field)`、`children`、`footer(..)`、`columns(n)` | `Form::new()` 的形态等于我们"标签在上"的排法 |
| `Field` | `label(..)`、`label_fn(Fn(&mut Window,&mut App)->E)`、`description(..)`、`required(bool)`、`visible(bool)`、`items_start/center/end`、`col_span` | 对得上 `form_field` 的"标签 + 控件" |
| —— | **`Field` 没有 `error`** | 错误态仍由我们画（`label_fn` 换色 + `Input` 红边框） |

**实际做法**：只换**外壳**，`common::form_field_with_error` 内部改用官方 `Field`，
**52 处调用点一行没动**。核源码得到的三条硬约束都写进了那个函数的注释：

1. `Field::render` **第一行是 `.flex_1()`** —— 放进 `v_flex` 会把字段竖向拉长，
   所以 `full` / 非 `full` 两种宽度都**显式覆盖**（`refine_style` 在 render 末尾，能盖住）；
2. 标签默认 `text_sm + font_medium`，我们的设计是 `text_xs` + 用变暗表达"必填未填"
   → 走 `label_fn` 自己画；
3. `Field` 内部给自己的包裹层 `.id(self.id)`，而 `self.id` 只有**经由 `Form` 的
   enumerate** 才被赋值；我们单独建 `Field` 所以 id 恒为 0。这些包裹层不挂任何
   hover / 点击 / 滚动，暂无可观测影响 —— **但哪天要在 `Field` 外壳上做悬停，
   就得改成由 `Form` 统一建**。这条也写进注释了。

**没做、但将来可以做的**：`Form` 的 `label_width` / `columns` 能把 8 个弹窗的
标签列宽统一（现在各弹窗的标签宽度靠内容自然撑开）；`Field::required(true)` 的
红色星号能替掉我们"标签变暗"那套暗示。两者都要重排弹窗布局，单独一批做。

### 2.6 官方 `Table`（静态表格）—— **已确认可用，已迁移**

**这一条原来的判断是错的，必须改**：我原先只看 `DataTable`（虚拟滚动 + 列管理），
结论是"我们的行内按钮 + 比例列宽它不支持，别迁"。核过 `table` 模块的源码后发现问题问错了 ——
官方有**两套**表格：

| 组件 | 是什么 | 适用 |
|---|---|---|
| `DataTable` + `TableDelegate` | 虚拟滚动、列宽拖拽、排序、单元格选择 | SQL 结果表（已用） |
| **`Table` / `TableHeader` / `TableBody` / `TableRow` / `TableHead` / `TableCell`** | **"simple, stateless, composable table without virtual scrolling or column management"** | **8 个列表页 + 备份表** |

核过 `src/table/table.rs` 的关键实现，确认三件事：

1. `TableRow::render` = `.w_full().flex().flex_row()` + `border_t_1()`（`ix > 0` 时）；
2. `TableHead` / `TableCell` 默认 `flex_shrink_1 + flex_basis(relative(col_span))`
   （**等分**），并且 `min_w(MIN_CELL_WIDTH = px(100.))`；
3. **`refine_style(&self.style)` 是最后一步** —— 所以我们的
   `flex_grow(fraction)` / `flex_basis(px(0.))` / `min_w_0()` 能覆盖官方默认值。

**唯一真实的约束**：`TableBody::children` 要求 `ChildElement`
（= `Sizable + IntoElement`），而 `AnyElement` **不**实现 `Sizable` ——
所以 8 个页面的 `rows` 必须写成 `Vec<TableRow>`，不能 `into_any_element()` 之后再塞进去。
这就是这轮 8 个页面都改了 `let rows: Vec<AnyElement>` → `Vec<TableRow>` 的原因
（**不是**类型推导的遗漏）。

**已完成**（v0.18 这一批）：`common::table_header` / `table_row` / `table_card` 三个助手
内部改成官方组件族，8 个列表页 + 备份表全部走它；调用点只剩"给列定义 + 给行 + 给空状态"。

**副作用（需要在实机上确认的地方）**：

- 行分隔线由官方的 `border_t_1`（第 2 行起）提供，不再是我们每行画 `border_b_1` ——
  视觉上等价，但**卡片底边那条线现在只由外层 `border_1` 提供**；
- 单元格内边距我们仍显式给 `px_2 py_2`（盖掉官方按 `Size` 算的内边距），
  所以行高应当与改造前一致；
- 表头底色官方默认铺 `tokens.table_head`，我们显式 `.bg(theme::bg_card())` 盖掉。

### 2.8 `GroupBox` vs `card()`

`GroupBox` 有 `title` / `title_style` / `content_style` / `footer` / `normal|outline|fill` / `id`。
我们的 `card()` 形状和它**几乎一样**（标题 + 内容 + 圆角 + 边框 + 底色）。
**收益**：`id` 能让卡片自己可悬停/可聚焦；`footer` 是现成的。
**代价**：`card()` 的颜色是 `theme::bg_card()` / `theme::border()`，`GroupBox` 会跟组件库主题走
—— 而本项目的 `theme.rs` 是**自己那一套**（`AGENTS.md` §5：颜色归我们，形态归组件）。
**结论：建议换**（形态归组件、颜色通过 `style`/`title_style` 覆盖），但**先在一张卡上试**，
确认能覆盖底色与边框颜色。**风险**：中（颜色覆盖面要核实）。

### 2.9 `Stepper` 用于安装步骤预览

「添加实例」页把 `install_model::plan()` 的步骤列表画出来（7 条 notes），
这正是 `Stepper { item: StepperItem }` 的形状（`selected_index` 表示"做到第几步"，
安装过程中进度也能直接喂给它）。**收益**：现在的"步骤预览"和"安装进度"是两套画法，
合成一个 `Stepper` 之后，预览 → 进行中 → 完成是**同一个控件换状态**，用户不用重新认一遍布局。
**风险**：中低。**验证**：实机走一遍 tar 导入。

### 2.10 `Skeleton` 替代"正在加载…"（可选）

15 处 `正在加载…/正在读取/正在执行`。**判断**：`Skeleton` 的收益是"感知性能"，
但本项目的等待大多**有明确的进度**（安装/部署/导入都有进度条），
剩下的表格首屏 3 秒刷新一次，用灰字反而是"轻"的。
**结论：不建议全铺**。只在**真慢**的那两处用（数据库页读表结构、`registry` 查 tag）——

**若采纳**：`common::skeleton_rows(n)` 一处封装，别在调用点写 `Skeleton::new()`。

### 2.11 `Separator` 替代 5 处 `border_b_1()`

5 处手写分隔线。`Separator` 的价值是"跟主题走 + 有垂直方向"。
**结论：可换，但不是问题**（5 处不算重复，样式也只有一行）。
**优先级最低**，顺手改即可。

### 3.1 `state/tests.rs`：2720 行、113 条断言、跨 10 个域

## 7. 浮层迁移进度（官方 `Dialog`）

官方 `Dialog` 是**窗口级层栈**（`WindowState::active_dialogs`，由 `Root` 渲染），
不是"另一种模态写法"。迁过去之后**层序 = 栈序**，
`modal_scrim` 的 `.occlude()`、入场动画 id、以及 `render.rs` 末尾那条手工层序链子
都可以逐步删掉。

### 已迁（16 / 19）

| 浮层 | 做法 |
|---|---|
| 单输入框提示（prompt） | 打开处已有 `&mut Window`；内容 `PromptContent` 子实体（observe 输入框） |
| 容器 exec | 同上；内容 `ShellView`（observe `Shell`） |
| 导出进度 | 由状态驱动 → 走 `sync_dialog_stack`；内容 `ShellView` |
| 通用 `ShellView` | 新件：把"读 Shell 状态画一块"包成会自动重画的子实体 |

### 查清的关键事实：官方**没有**"按 id 关对话框"

- `ActiveDialog` **没有 id 字段**（只有 focus_handle / builder 等）；
- `WindowExt` 只有 `close_dialog`（关栈顶）/ `close_all_dialogs` / `has_active_dialog`；
- `Root::close_by_type(TypeId, key)` 是**通知条**的，不是对话框。

所以 `Shell::sync_dialog_stack` 用**最长公共前缀**对齐：
多的从栈顶 pop（安全）、缺的依次追加（不动下层）、非前缀乱序才 `close_all` 兜底。

### 两个必须知道的官方行为（都是实机/源码踩出来的）

1. **builder 闭包只在层重建时重跑** —— 打字、后台任务推进都**不**触发它。
   所以任何"内容会变"的浮层，内容必须包在 `PromptContent` / `ShellView` 这类
   **子实体**里，否则会僵在打开那一刻（v0.19.0 的 bug）。
2. **普通 `Dialog` 不会自动画 OK / Cancel** —— 那是 `AlertDialog` 的行为。
   `DialogButtonProps::render_ok/render_cancel` 只有 `AlertDialog` 调；
   `Dialog::render` 只看 `self.footer`，`show_cancel` 默认 `false`。
   底部按钮必须自己 `.footer(modal_footer([...]))`。
