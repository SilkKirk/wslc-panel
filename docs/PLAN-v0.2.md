## 2. P0 — 先修 `storagePath` 显示（你截图里红框那个）

### 问题根因

`settings.yaml` 里所有配置项**出厂都是注释状态**：

```yaml
  # storagePath: default
```

我们读到的值就是"未设置"，于是界面上显示成 `(默认: %LOCALAPPDATA%)`。
这句话本身没错，但**用户看不到真实的落盘位置**，等于没显示。

而且 `wslc info` **也不报**这个路径 —— 它只给 `SettingsFile`：

```
.Client.SettingsFile = C:\Users\76434\AppData\Local\wslc\settings.yaml
```

### 真实语义（来自 settings.yaml 自带注释）

> Base directory for the default session's storage; the session VHD is created at
> `<storagePath>\wslc\sessions\<session>\storage.vhdx`. Must be an absolute path
> (e.g. `D:\data`, default: `%LOCALAPPDATA%`).

所以默认情况下 **VHD 的真实位置是**：

```
C:\Users\76434\AppData\Local\wslc\sessions\wslc-cli-76434\storage.vhdx
```

（实测该文件 **612 MB**，与本机 `%LOCALAPPDATA%\wslc\sessions` 的占用一致。）

### 修改方案

`storagePath` 这一行改成显示**解析后的实际信息**，而不是"默认值"三个字：

```
存储
  配置文件        C:\Users\76434\AppData\Local\wslc\settings.yaml
  storagePath    未设置 → 实际使用 %LOCALAPPDATA%
  会话磁盘       C:\Users\76434\AppData\Local\wslc\sessions\wslc-cli-76434\storage.vhdx
  磁盘占用       612.00 MB                    [打开所在文件夹]
```

要点：

1. 值为空/`default` 时，把 `%LOCALAPPDATA%` **展开成真实路径**再显示；
2. 会话名从 `wslc info` 的 `Server.Sessions[0].Name` 拿（已有 `session_label()`）；
3. 文件不存在时如实显示"尚未创建"（新建会话前就是这样），**不要伪造**；
4. 路径过长要能换行/省略，不能让长路径把布局撑破。

> 这一项不依赖任何新能力，**可以立刻做**。

## 3. P1 — 磁盘占用（概览页）

### 关键约束：`wslc` 没有 `system df`

实测 `wslc system` 只有 `events` / `info` / `session` 三个子命令，**没有磁盘统计**。
所以不能照抄 1Panel 那张卡 —— 它背后是 `docker system df`。

### 我们能拿到什么

| 指标 | 数据来源 | 精度 |
|---|---|---|
| 会话磁盘（VHD）实际占用 | 文件系统：`storage.vhdx` 的 `Length` | ✅ 精确 |
| 所在卷剩余空间 | 文件系统 | ✅ 精确 |
| 镜像合计大小 | `wslc images` 的 `Size` 字段求和 | ✅ 精确（会重复计共享层，需注明） |
| 容器可写层占用 | —— | ❌ **不可得** |
| 卷占用 | —— | ❌ **不可得** |
| 构建缓存 | 未发现独立目录 | ❌ 暂不可得 |

**为什么容器/卷拿不到**：它们和镜像**共用同一个 `storage.vhdx`**，
在 Windows 侧是一个不透明的虚拟磁盘文件。要分开只能进容器内部跑 `du`，
既慢又依赖容器里有 `du`，不值得做。

### 修改方案

概览页新增一张「磁盘占用」卡，**如实标注来源**：

```
磁盘占用
  会话磁盘    612.00 MB      C:\...\wslc-cli-76434\storage.vhdx
  镜像合计    3.49 GB        4 个镜像（含共享层重复计算）
  容器可写层  —              与镜像共用同一 VHD，无法单独统计
  所在盘可用  118.7 GB / 476.9 GB (C:)
```

再补一张「存储位置」卡（就是 P0 那些信息的概览版）。
`storage.vhdx` 的行内给一个"打开所在文件夹"按钮（`explorer /select,<path>`）。

## 4. P2 — 镜像页：拉取 / 删除 / 详情

### 4.1 工具栏

镜像页顶部加一条工具栏（照 1Panel 的位置）：

```
[拉取镜像]  [导入…]  [构建…]        搜索: [____]  [刷新]
```

先做**拉取镜像**（导入/构建留到 v0.3，需要文件选择器和 Dockerfile 编辑）。

### 4.2 拉取镜像弹窗

| 字段 | 说明 |
|---|---|
| 镜像引用 | 必填，如 `alpine:latest`、`docker.1ms.run/library/nginx:latest` |
| 全部标签 | 复选，对应 `-a/--all-tags` |

底部显示**等效命令**：`wslc pull docker.1ms.run/library/nginx:latest`

**必须给出加速地址提示**：本机实测直连 `registry-1.docker.io` 会超时，
而用户现有镜像的 Repository 是 `docker.1ms.run/...`。表单里直接提示：

> 直连 Docker Hub 在本机不可达，请使用镜像加速地址，
> 例如 `docker.1ms.run/library/<名称>:<标签>`。

### 4.3 长任务的进度反馈（新增能力）

`wslc pull` 可能跑几十秒到几分钟，**不能只转圈**。需要：

1. 弹窗里显示一个"进行中"状态 + 已用时；
2. 流式读取子进程输出，显示**最后一行**（`Pull complete` / `Downloading` 之类）；
3. 允许取消（`Child::kill`）。

数据层已有 `run_cancellable`，但**没有"边跑边读"的接口**。
需要在 `wslc-core::cli` 增加一个 `run_streaming(wslc, args, on_line)`，
用已有的并发读线程模式，把每行回调出去。

### 4.4 行内操作

- **创建容器**（带上该镜像引用，跳到 P3 表单）← 这是最顺手的入口
- 删除镜像（已有 `PendingAction::RemoveImage`）
- 清理未使用镜像（`wslc image prune`，需确认弹窗）

## 5. P3 — 创建容器（核心功能）

### 5.1 入口（两处，照 1Panel）

1. 「全部容器」页工具栏的 **[创建]** 按钮
2. 「镜像」页每行的 **创建容器**（镜像引用预填）

### 5.2 表单（分组，照 1Panel 的弹窗）

| 分组 | 字段 | 对应参数 |
|---|---|---|
| 基本信息 | 镜像引用*、容器名、启动命令、工作目录、运行用户、主机名 | `<image> [cmd]`、`--name`、`-w`、`-u`、`-h` |
| 运行方式 | 后台运行 `-d`（**默认勾选**）、停止后自动删除 `--rm` | `-d`、`--rm` |
| 端口 | 可增删的 `主机端口:容器端口` 行 | `-p` |
| 环境变量 | 可增删的 `KEY=VALUE` 行 | `-e` |
| 卷 | `卷名:容器内路径` 行，卷名可从已有卷下拉 | `-v` |
| 网络 | 下拉（已有网络 + `bridge`） | `--network` |
| 资源限制 | 内存（如 `512M`）、CPU（如 `0.5`） | `-m`、`--cpus` |
| 镜像拉取策略 | `always` / `missing`（默认）/ `never` 三选 | `--pull` |

`--pull` 那一项**必须有说明文字**：

> 本机连不上 Docker Hub 时选 `never`（只用本地已有镜像），
> 否则 `wslc` 会卡在拉取上直到超时。

### 5.3 底部「等效命令」预览（强烈建议）

用已有的 `RunSpec::to_args()` 直接生成，实时显示：

```
wslc run -d --name web --pull never -p 8080:80 -e TZ=Asia/Shanghai \
  -v webdata:/usr/share/nginx/html nginx:latest
```

好处：用户随时知道我们在跑什么；出问题可以直接复制到终端复现。

### 5.4 提交后

关闭弹窗 → 顶部提示"正在创建…" → 成功后刷新列表并**跳到「当前运行」页** → 成功/失败都给明确提示。

### 5.5 ⚠️ 一个必须处理的陷阱

`wslc run` **不带 `-d` 时容器在前台运行，我们的子进程会一直挂着**。
而执行层默认超时 30 秒。

处理方式（二选一）：

- **推荐**：表单里 `-d` 默认勾选，并在不勾选时提示"前台模式会开一个独立控制台窗口"；
- 走已有的 `spawn_in_new_console`，把前台容器的 stdout/stderr 交给一个真实控制台。

## 6. P4 — 列表页通用能力

1. **搜索框**：客户端过滤（名称/ID/镜像/端口），不增加 `wslc` 调用；
2. **列头排序**：点击切换升/降序（复用已有的解析结果，纯内存排序）；
3. **行内操作收纳**：操作多于 3 个时收进"更多"菜单，避免表格拥挤；
4. **底部条**：`共 N 条` + 每页条数（先做 `全部 / 20 / 50`，数据量小可不分页）；
5. **行首复选框 + 批量操作**：容器页已有删除，可扩展到镜像/网络/卷。

> 前三项收益最大，建议先做。分页在容器/镜像数量 < 100 时作用有限。

## 8. 前置条件与风险（必须先解决）

### 🔴 8.1 没有输入控件 = 拉取和创建都做不了

目前 `wslc-panel` **一处 `InputState` / `TextInput` 都没用**。
配置页当时是刻意跳过自由文本输入的（只做预设按钮 + 原始 YAML）。

**拉取镜像要输入镜像名、创建容器要输入 6+ 个字段 —— 躲不过去。**

所以第一步应该是**最小验证**：做一个只有一个输入框的弹窗，跑通：

1. `InputState::new(window, cx)` 的构造与持有（GPUI 里输入框状态必须是 `Entity<InputState>`）；
2. 在 `Shell` 里存 `Entity<InputState>` 的字段；
3. 从 `InputState` 读回文本（`state.value(cx)`）；
4. 弹窗打开时把焦点给它。

**这一步不跑通，P2/P3 全都写不了。** 建议作为独立的第一步先验证。

### 🟡 8.2 拉取进度的输出格式未采样

`wslc pull` 往 stdout 还是 stderr 写、格式如何，**还没实测**（本机连不上 registry）。
需要先拿一个小镜像（如 `alpine`）跑一次采样，再定流式解析。

### 🟡 8.3 `storagePath` 改动不会迁移已有数据

settings.yaml 自带注释明确写了：改了之后**已有容器/镜像/卷不会跟着搬**，
原位置留着，并在新路径新建一个**空会话**。

UI 里已经有 `needs_warning` 标记，v0.2 要把这段警告写成**二次确认弹窗**
（当前只是在配置项旁边标了一下）。

### 🟢 8.4 已就绪的部分

`RunSpec` / `PullPolicy` / `cmd::image::pull` / `cmd::container::{run,create,prune}`
都已经写好并过了单测，**不需要动数据层**（除了 8.2 的流式接口）。

## 9. 建议的实施顺序

| 步骤 | 内容 | 依赖 | 风险 |
|---|---|---|---|
| **1** | P0：修 `storagePath` 显示 | 无 | 低 |
| **2** | P1：磁盘占用 + 存储位置卡 | 步骤 1 | 低 |
| **3** | **前置验证**：接 `InputState`（最小弹窗） | 无 | **中高 —— 卡住则 4/5 都做不了** |
| **4** | P2：拉取镜像（含 `run_streaming`） | 步骤 3 | 中（输出格式待采样） |
| **5** | P3：创建容器表单 | 步骤 3 + 4 | 中（前台模式陷阱） |
| **6** | P4：搜索 / 排序 / 行内操作收纳 | 无 | 低 |
| **7** | P5：视觉打磨 | 全部 | 低 |

**建议先做 1 + 2（立刻能用），同时把 3 作为独立小任务验证掉**，
确认 `InputState` 没问题之后再铺 4 和 5。

## 10. 需要你确认的点

1. **实施范围**：先做 1+2+3（修 bug + 磁盘占用 + 输入控件验证），还是直接一路做到 6？
2. **`storagePath` 要不要支持修改？** 它改了会新建空会话、不迁移数据，
   风险不小。建议 v0.2 **只读展示 + 打开文件夹**，写入留到以后。
3. **镜像加速地址**：是否把 `docker.1ms.run` 作为默认前缀写进拉取表单？
4. **前台运行（不带 `-d`）**：是干脆不支持（强制 `-d`），还是开独立控制台？
